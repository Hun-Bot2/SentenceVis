# AI-Hub 전수 확인과 데이터 간 교차 검증 (2026-11-16)

- **상태:** [VERIFIED] 아래 수치는 로컬 원본을 실제로 실행해 얻은 결과다. 검증 대상은 **AI-Hub 자료끼리 서로 일치하는지**다. 법률적 정답 검증이나 사람 검토는 포함하지 않는다(사람 검증 0건).
- **작성:** Claude Code (Anthropic, Claude Opus 5.5). AI 사용 기록은 [ATTRIBUTION](../records/ATTRIBUTION.md)에 있다.
- **재현:**

```bash
python3 -I scripts/ingest/aihub_scan.py data/private/aihub_scan/<새 폴더>          # 전수 스캔, 약 40초
python3 -I scripts/ingest/aihub_crosscheck.py data/private/aihub_scan/<그 폴더>     # A–D 교차 검증
python3 -I scripts/ingest/aihub_textdiff.py data/private/aihub_scan/<그 폴더>       # 본문 차이 원인 표본 분류
```

출력은 모두 `data/private/aihub_scan/`에 저장되며 Git에서 제외된다. 불일치는 항목마다 양쪽 값과 함께 `crosscheck_mismatches.jsonl`에 기록한다.

## 4. 프로젝트에 주는 함의

1. **연결 규칙의 외부 근거:** 사람이 작성한 019 원심 주석과 비교했을 때 자동 연결은 53/56 일치한다. 다만 019 자체에도 오류가 있으므로 사람 정답이 아니다. **독립 출처와 일치한다는 근거**로만 쓴다.
2. **형사 코퍼스의 규모:** 일련번호 기준으로 중복을 제거한 형사 판례는 15,874건이다(12 2,992 + 115에만 있는 12,882). 그런데 1심↔항소심 자동 연결은 237건으로 거의 늘지 않는다(12만 쓸 때 219건). 115에 추가된 형사 판결은 대부분 대법원 판결이기 때문이다.
3. **개인정보:** 115 원문에는 12에서 가려진 실명과 지번이 남아 있는 문서가 있다. 화면이나 공개 산출물에서는 **원문 표시를 12의 익명화본 기준으로 하고**, 115에만 있는 문서는 별도로 익명화하기 전까지 원문을 표시하지 않는다(AGENTS.md 금지사항).
4. **연결 누락:** 019가 원심을 가리키지만 연결하지 못한 9건과, 019가 가리키는 원심이 로컬 코퍼스에 없는 279건이 남아 있다. 앞의 것은 규칙 개선 대상이고, 뒤의 것은 자료 범위의 한계다.
5. **아직 하지 않은 것:** 3심(대법원) 연결 규칙, 019 주장·판단 주석과 이유 단서의 대조, 114 트리플 내용의 상세 검사.


## 5. 법률 지식베이스 추가분 (2026-11-16)

- **정체:** URI 이름공간이 `http://www.aihub.or.kr/kb/law/`이고 파일명이 `nia_law_*_20180117`인 **AI-Hub 법률 지식베이스**(NIA, 2018-01-17 기준)다. ZIP 17개를 모두 스트리밍으로 읽었다. N-triple 파일 전체에서 형식이 깨진 줄은 0줄이다.
- **구성:** 법령용어 사전(주어 246,045개), 법령지식 4종(관련판례 77,382·교통사고 2,500·창업인허가 14,293·층간소음 1,195개 주어), 법률데이터(법령·조문, 생활법령 질의응답, 법관·재판부), OWL 모델 7개.
- **JSON ↔ N-triple 대조:** 5개 데이터셋 모두 주어 집합이 일치한다. 차이가 나 보였던 45개는 빈 노드 이름 앞의 `B` 접두어 차이뿐이다. 값 수와 트리플 수는 법령지식 4종에서 완전히 같고(관련판례 1,288,333), 법령용어만 507개 차이가 있다(원인 미조사).
- **지식베이스 판례 노드 ↔ 12·115 판례 (일련번호 대조):** 노드 77,292개 중 36,399개가 대응한다(형사 11,670). 사건번호 98.32%(불일치 613건 중 612건은 병합번호 표기 차이), 법원 99.99%, 선고일 99.99%, 사건종류 99.98% 일치. 지식베이스 참조조문 96,730개 중 99.55%가 판결 원본의 `참조조문`에서 텍스트로 확인된다.
- **지식베이스 쪽 데이터 오류:** 존재하지 않는 날짜 `19680878`, 7자리 날짜 `2001713`, 원본과 다른 선고일(06-04 ↔ 06-13), 형사 판결이 `특허`로 분류된 경우. 모두 불일치 장부(`E_kb`)에 기록했다.
- **새로 더해 주지 않는 것:** 하급심(고·노) 형사 판결의 지식베이스 참조조문은 원본에 `참조조문`이 있는 판결에만 있다. 원본에 없는 하급심 1,048건은 지식베이스 값도 빈 문자열이다. *처음에는 빈 문자열이 든 리스트를 값이 있는 것으로 세어 "1,010건을 보충한다"고 잘못 판단했고, 다시 확인해 정정했다.* 또 참조조문은 `법령의 적용`이 아니다(AGENTS.md).
- **법령 판본:** 조문 노드 12,642개는 법령 132개에 대해 **법령마다 판본이 하나씩**(시행일 2002-09-01~2019-07-01)뿐이다. 판결 당시의 법령 판본(D-008)을 제공하지 못하므로 조문 본문은 `contextual`로만 쓸 수 있다.
- **개인정보 주의:** `법률데이터_판례`의 법관·재판부·재판부구성 노드는 법관 실명을 담고 있다. 인터페이스 범위에 필요하지 않으므로 사용하지 않는다.
- **재현:** `python3 -I scripts/ingest/kb_scan.py <스캔 폴더>`(약 1분) → `python3 -I scripts/ingest/kb_crosscheck.py <스캔 폴더>`.
