- 조사일: 2026-11-16 KST
- 판단: **2002–2011년 항소심 선고 기간을 유지하고, 추출·연결·검증을 먼저 보완한다.** 현재 자료로 원문 기반 V1–V3 파일럿을 구성할 근거는 있다. 전체 구현·평가에 충분한 검증 데이터가 확보됐다는 뜻은 아니다.
- 검토자: OpenAI Codex 단독 원문 대조. **사람의 법률 검증 완료 건수는 여전히 0**이다. 아래의 `원문대조 지지`는 AI가 저장된 두 원문을 직접 읽고 일치 근거를 기록한 상태이며, 법률 전문가 검증·법원 원본 대조·실제 인물 신원 확인을 뜻하지 않는다.

## 2. 187개·94개 후보의 산출 근거와 재현 가능성

### 2.1 확인한 근거와 찾지 못한 것

슬라이드 p.2·p.7에는 `원심판결 사건번호 + 법원 + 죄명`, 제외 후보 16개, 연결 187개, 양쪽 주문에 징역이 있는 94개, 그중 공동피고인 43개라는 설명이 있다. 그러나 **원래 후보 ID 목록, 제외 16개 목록, 실행 코드·버전, 법원 별칭/병합번호 처리 규칙은 발견하지 못했다.**

검색 범위는 현재 `scripts/`, `tests/`, `docs/`, `data/`의 후보·매니페스트 파일 목록, 현재 Git 전체 이력의 두 커밋(`be836a4`, `0319846`) 및 스크립트 이력이다. 사용자 기기 전체나 다른 저장소까지 검색한 결과는 아니다. 문서에서 같은 수치를 반복한 것은 독립 재현 근거로 세지 않았다.

기존 SQLite의 `pairing_candidates`는 **원천 JSON↔라벨 JSON 표현 연결**이다. 이를 1심↔항소심 연결로 사용하지 않았다. 이번에는 그 연결을 통해 원천 `PrecService.판례내용`과 라벨 `sections`를 함께 읽었다.

### 2.2 규칙을 명시한 재산출 실험

모집단은 일반판결 라벨의 `형사/형사A/형사B` 2,700문서다. 항소심 날짜를 2002–2011년으로 제한하고 원심 문서는 전체 모집단에서 찾았다. 아래 수치는 모두 **자동 후보**이며 피고인 정렬 정답이 아니다.

## 3. 표본 설계와 직접 대조 범위

1. 기존 175 edge에서 슬라이드 대표 사례를 우선 포함했다.
2. 각 관측 항소 연도의 날짜·source ID 정렬상 첫 후보를 포함했다.
3. 여러 원심을 가리키는 항소 문서, 법원 표기의 다양성을 포함해 25 edge를 선정했다. 단독 피고인뿐 아니라 복수·분리·병합 사건이 포함된다.
4. P12는 P11과 **같은 양끝 source ID**인 중복 edge여서 독립 사건쌍에서 제외했다. `2005고단4554-1`을 정규식이 `2005고단4554`로 잘라 만든 추가 매칭이었다.
5. 2011년 후보 0건을 별도 조사해, 복합 원심 키 때문에 누락된 P26을 추가했다.

최종 분모는 **서로 다른 사건쌍 25개, 항소 문서 23개, 원천 판결 문서 48개**다. P11/P13, P14/P15는 각각 같은 항소심에 연결된 서로 다른 원심이며 항소 결과를 중복 집계하지 않는다. 원천과 라벨은 별도 판결로 세지 않는다.

- 항소 연도별 표본: 2002 1, 2003 1, 2004 3, 2005 4, 2006 7, 2007 4, 2008 1, 2009 2, 2010 1, 2011 1.
- 항소 법원 표기는 16종, `지법/고법` 약칭만 정규화하면 13종이다. 역사적 법원 명칭의 법률적 동일성을 일괄 확정하지 않았다.
- 원심에 단독, 2·3·5·6명의 피고인, 7·8번까지 등장하는 분리·병합 사례가 포함된다. **가장 큰 피고인 번호를 실제 인원수로 사용하지 않았다.** P03처럼 복수 표현만 있고 인원/대응이 불명확한 자료도 포함한다.
- 확률 표본이 아닌 **실패 유형을 찾기 위한 목적 표본**이다. 아래 비율을 전체 187/206개, 전체 연도, 한국 항소심의 성능·성공률로 일반화하지 않는다.

각 쌍의 양쪽 사건정보·원심 참조·주문을 읽고, 연결이 지지되는 경우 선택한 항소이유와 대응 판단·결론 및 필요한 원심 사실/역할을 대조했다. 긴 판결의 모든 쟁점·별지·역사적 조문을 완전 주석한 것은 아니다. 명백한 오연결은 연결 단계에서 중단했으며, 그 이후 항목을 원문 결측으로 분류하지 않았다.

### 4.1 기존 파서의 손실을 실측한 결과

| 같은 표본 문서 48개의 검사 | 발견 문서 수 |
|---|---:|
| 원천 JSON의 `【주문】` | **48/48 (100%)** |
| 라벨 JSON에서 공백 제거 후 제목이 정확히 `주문` | **2/48 (4.2%)** |
| `#이름#` 제목 아래 선고/파기/기각 문구가 있는 라벨 section | **44/48 (91.7%)** |

따라서 이 표본의 낮은 주문 포착률은 원문 부재보다 **표현 선택과 표제 의존 추출의 실패**로 설명된다. 단, 전체 데이터의 재현율을 4.2%라고 주장하지 않는다. `#이름#` 전부를 주문으로 일괄 치환해서도 안 된다. 원천의 해당 구절과 대조해야 한다.

항소이유도 대개 라벨의 별도 `항소이유` section이 아니라 `이유` 내부에 `1. 항소이유의 요지 → 2. 판단`으로 들어 있다. 기존의 전용 제목 감지 1문서는 항소이유가 있는 전체 문서 수가 아니다.

### 4.2 단계별 구체적인 실패

- **번호 연결 오류:** P09/P18은 죄명까지 같지만 원심 법원·날짜가 다르다. P21은 본원과 지원을 부분문자열로 맞추면 통과하고, 원심 후보 날짜가 항소심보다 늦다. 연도를 2009년 이후로 옮겨도 고유하지 않은 사건번호 조인은 해결되지 않는다.
- **복합 키 손실:** P26의 원심은 여러 병합 사건번호를 하나의 메타데이터 값으로 가진다. 단일 번호와 전체 문자열의 완전일치가 실패했다. 기존의 2011년 후보 0건은 이 문서쌍의 부재를 뜻하지 않는다.
- **실제 미확보 가능성:** 로컬 2011년 항소 패턴 4문서를 모두 조사했다. P26 외 3문서의 확인한 원심 번호는 로컬 메타데이터 부분문자열 검색에서도 발견되지 않았다. 축약 번호·다른 데이터셋까지 모두 복원한 검사가 아니므로 `로컬 검색 미발견`으로 남긴다.
- **피고인 정렬:** P14에서 제2원심의 피고인1과 항소심 피고인3 사이에 벌금액·역할 대응 단서가 있다. 동일 번호=동일 피고인 규칙은 위험하다. P17은 반대로 차량·진행방향·무죄 부분을 대조해 원심 피고인2가 항소심 단독 피고인임을 지지할 수 있었다.
- **형량 모델의 한계:** P02/P08은 한 사람에게 구분된 복수 형이 있다. P23은 일부만 징역→벌금으로 바뀐다. P19/P25 본문에는 다른 사건의 징역 전력이 등장한다. 첫 `징역` 숫자 추출, 복수 형 합산, 벌금/무죄를 0개월로 변환하는 방식은 금지해야 한다.

## 9. 증거 파일·재현·보존 검증

비공개 조사 루트: [`data/private/temporal_scope_audit/2026-11-16/`](../../data/private/temporal_scope_audit/2026-11-16/). 원문·개인정보·이용권 미확인 자료를 공개 Git이나 브라우저로 내보내지 않는다.

- `P01.json`–`P26.json`: P12 중복 진단 포함. 원천/라벨 내용, source ID, ZIP 경로·member index·member SHA-256·archive SHA-256, 메타데이터와 읽기용 텍스트. **P12는 최종 장부에서 제외**.
- `sample.json`, `candidate_profiles.json`: 최초 선정 규칙/분모. 최종 표본은 `review_decisions.jsonl`의 25개 ID이며, P26은 2011년 진단에서 추가했다.
- `reconstruction.json`, `reconstruction_compound.json`: 각 재산출 규칙의 후보 및 집계. 토큰 적중 218회와 중복 제거 206쌍을 구별한다.
