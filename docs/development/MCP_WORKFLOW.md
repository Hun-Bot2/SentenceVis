# MCP WORKFLOW — SentenScope 데이터 수집·검증·분석 운영

> **문서 위치 정리:** 기존 운영 계획을 보존한 문서다. 2026-11-13의 이번 UI 런타임 조사에서 API/MCP 서비스 주장을 모두 재검증한 것은 아니다. 실제 개발 기반은 [ENGINEERING](ENGINEERING.md), 미확인 데이터는 [VALIDATION](../specs/VALIDATION.md)을 따른다.

> 상태: `[PLAN]` (2026-11-13). 기존 `DATA.md`, `VALIDATION.md`, `ENGINEERING.md`, `TASK.md`를 구현하기 위한 운영 절차다. **실제 데이터 수집·검증을 완료했다는 뜻이 아니다.**

## 1. 핵심 원칙

SentenScope의 재현성은 **원본과 결과를 모두 공개하는 것**이 아니라, **합법적으로 확보한 원본에서 동일한 파생 결과를 재생성할 수 있는 절차와 근거를 남기는 것**이다. 원본, API 키, 심사 대상 개인 데이터는 공개 GitHub에 넣지 않는다.

- 원본 데이터 → 개인/승인된 보안 환경에 보관, Git 제외.
- 처리 규칙 → `scripts/`, `src/domain/`, `src/data/`, `tests/`로 버전 관리.
- 검증 상태 → 기계적 연결 후보와 사람이 확인한 정답을 구별.
- 결과 → 허가된 집계·익명화·비식별·최소 정보만 공개.
- LLM 추론 → `candidate`로 기록, 법률적 정답으로 자동 승격 금지.

## 3. 운영 순서와 완료 조건

### P0. 저장소 접근·권리·보안 확인

- [ ] GitHub MCP에서 SentenScope 저장소가 열리는지 확인. 원본 데이터를 커밋하지 않도록 `.gitignore`를 우선 반영.
- [ ] 데이터셋의 이용 허가/출처·최신 약관·논문 인용 조건을 기록.
- [ ] `.env`를 제외하고 로컬 `OC` 인증정보를 `LAW_API_OC` 등 환경 변수로 저장.
- [ ] `data/raw/`, `data/private/`, `data/cache/`, 사용자 연구 원자료는 Git 제외.
- [ ] 앱 공개 데이터와 평가 전용·민감 원자료를 별도 경로로 유지.

**Gate:** 저장소 접근 가능 + 키 비노출 + 원본 공개 차단 + 이용 조건 기록.

### P1. 원본 아카이브 수령·무결성 검사

- [ ] 연구자가 정당하게 제공받은 ZIP은 먼저 허가된 보안 환경에서 처리. 이 채팅에 원본 전체를 업로드하는 행위가 허용되는지는 이용 조건을 별도로 확인. 허용되지 않으면 원본은 로컬에 두고 메타데이터·집계 결과만 업로드.
- [ ] ZIP 엔트리 크기·경로 검사(zip-slip, zip bomb 방지), 중복 파일·인코딩 확인.
- [ ] 파일별 SHA-256, 확장자, 크기, JSON 스키마 샘플, 문서 수를 산출.
- [ ] `data/private/manifests/source_manifest.json`, `artifacts/validation/raw_inventory.md`, `artifacts/validation/quality_baseline.json` 생성.
- [ ] 원본 전문 대신 파일명·해시·집계량을 대화/저장소 공유 대상으로 우선 선택.

**Gate:** 실제 확보된 자료의 문서 수와 파일 구조를 재현 가능한 방식으로 설명할 수 있음.

### P2. 판결문 연결과 피고인 정렬

- [ ] 판결문 메타데이터·섹션을 표준 스키마로 변환.
- [ ] 원심판결 표기에서 사건번호·법원·죄명을 기준으로 사건쌍 **후보** 생성.
- [ ] 동일 사건번호의 중복·역전·누락·복수 후보 탐지.
- [ ] 공동피고인 별칭·순서·주문을 정렬하고, 모호한 경우 `unreviewed` 유지.
- [ ] `case_pairs`, `defendants`, `judgments` 분모를 분리해 보고.

**Gate:** 검증된 링크만 피고인별 형량 비교에 포함. 미검증 후보는 별도 표시.

### P3. 항소이유·판단·원문 근거 추출

- [ ] `appeal_ground`, `origin`, `disposition`, `reasoning_change` 추출 코드와 판단 규칙 작성.
- [ ] `source_basis`와 `verification_status`를 별도로 저장.
- [ ] 문서 ID, 섹션 경로, 텍스트 위치, 원본 해시를 관계에 첨부.
- [ ] LLM 추출은 사람의 검토 전 `unreviewed`; 확정할 수 없는 경우 `unclear` / `not_reached` 분리.
- [ ] 가능한 경우 독립 주석자 일치율·조정 결과 기록.

**Gate:** 각 검증된 시각적 경로가 실제 근거 문장으로 역추적됨.

### P4. 과거 법령 연결

- [ ] 판결문에서 **법령의 적용** 항목을 먼저 확인.
- [ ] 연혁 목록에서 정확한 법령 버전 식별; 사건의 범행 시점·경과규정·법원의 적용 판단 확인.
- [ ] HTML 전용 연혁 API와 JSON/XML 제공 API를 별도 파서로 처리하고 원문 구조를 검증.
- [ ] 수집 시점·법령 ID·판본·조문 번호·해시 보존.
- [ ] 단순 언급을 `applied`로 승격하지 않음.

**Gate:** 법령 버전과 법적 적용 근거가 확인되지 않으면 관계를 `uncertain`으로 남김.

### P5. 분석 및 연구용 산출물

- [ ] 항소 변화 방향, 집행유예 전환, 직권판단 비중 등 **정의된 분모**로 탐색적 분석.
- [ ] 데이터 품질 리포트: 결측·중복·오정렬·검증 상태·사건 분포·샘플 편향.
- [ ] User Study용 `gold_cases`와 검증 불가 사례를 별도 분할.
- [ ] 합법적으로 배포 가능한 최소 JSON·CSV만 UI에 연결.
- [ ] 사람이 확인한 결과와 추출 후보를 혼합하지 않은 ZIP 결과물 제작.

**Gate:** 보고서 통계·표·시각화·실험 문항을 소스 버전과 분석 코드로 재생성 가능.

## 4. 개발 기반과 운영 출력 경로

폴더 책임의 단일 명세는 [ENGINEERING](ENGINEERING.md)과 [소스 경계](../../src/README.md)를 따른다. 아래 데이터 파이프라인은 미구현 계획이며 폴더 존재가 처리기 구현을 뜻하지 않는다.

```text
scripts/
  ingest/                  수집·정규화
  align/                   사건쌍·피고인 대응
  annotate/                추출 후보·검토 자료
  statutes/                법령 조회·파싱
  publish/                 공개 검토 export
src/domain/ + src/data/    계약/검증 구현 예정
tests/                    단위·통합·브라우저 검사
data/raw/                 비공개 원본
data/private/             비공개 근거·manifest
data/processed/           비공개 파생
data/cache/               향후 비공개 캐시 (아직 미생성)
artifacts/validation/     로컬 감사 출력, 공개 검토 전 Git 제외
public/data/              검토된 export 목적지, 현재 자동 제공 비활성
```

## 5. 매 단계 결과 전달 계약

**입력:** 원본 ZIP 또는 허용된 API 결과; 데이터 출처와 허가 상태; 수집 시점; 스키마/코드 버전.

**결과 ZIP 예시 (`sentenscope-stage1-inventory.zip`):**

```text
manifest.json                  # 출처·해시·수집시점·코드 버전
raw_inventory.csv             # 문서별 익명 식별자·크기·필드 상태 (원문 없음)
quality_report.md             # 파일구성, 결측·중복·파싱오류, 한계
schema_summary.json           # 실제 데이터의 필드와 데이터 유형
errors.csv                    # 오류 코드와 해당 익명 문서 ID
README.md                     # 재현 방법, 공개/비공개 구분
```

개별 원문이 포함된 결과 ZIP은 명시적으로 내부용으로 구분하고 공개용 결과와 분리한다. **ZIP으로 포장했다고 재배포 허가가 생기는 것은 아니다.**

## 6. 첫 실행의 작업 범위

**작업 1: AI-Hub 원본 ZIP 구조 분석.** 승인된 로컬 환경에서 파일 수, 폴더 계층, JSON 필드, 법원/심급/기간·형사 판결 비중을 재계산한다. 외부 분석 서비스로 원본을 전송할 권리가 확인되지 않으면, 여기에는 원문이 없는 집계 결과와 스키마만 전달한다. 이 단계에서는 LLM 법률 판단을 추출하지 않는다.

**작업 2: 이전 제안서 수치 검증.** `2,700 / 187 / 94 / 43`의 계산 로직을 실제 원본 데이터에서 재현하고 차이를 설명한다.

**작업 3: 연결 후보 검증 샘플.** 사건쌍 5개를 선별해 근거 문장을 검사하며, 공동피고인 사건을 반드시 포함한다.

**작업 4: 법령 API 수집기.** 수동 검증한 사례에 등장하는 법령만 조회해 정확한 연혁 판본을 보관한다.

**진행 조건:** 로컬 원본 스캔 산출물이 제공되거나, 이용 조건상 허용된 데이터가 연결된 환경에서 접근 가능해야 실제 수치 산출을 시작할 수 있다. MCP 연결이 있다고 해서 모든 외부 데이터 접근 권한이 자동으로 생기는 것은 아니다.

## 7. 검증 가능성과 연구적 금지사항

- 미검증 후보 수를 정답 건수로 표시하지 않는다.
- 법률적 인과 효과를 단순 인접 관계로 추정하지 않는다.
- LLM 추출 결과는 원문 검증 없이 gold label로 사용하지 않는다.
- 과거 판결에 현행 법률을 소급 적용하지 않는다.
- 수집 승인, 저작권, 참가자 동의, IRB 요구를 구현 편의로 우회하지 않는다.
- `PAPER.md`에는 완료된 결과와 아직 검증 중인 가설을 구별해 기록한다.
