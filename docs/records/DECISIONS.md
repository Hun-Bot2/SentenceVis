## D-009 · 설계 선택권과 Tutor 방식

- **상태:** accepted / 2026-11-13 사용자 명시 요청.
- **규칙:** 에이전트는 근거 자료와 단계별 탐구 힌트를 제공한다. 디자인의 “왜?”를 대신 답하거나 축·도형·색·배치를 확정하지 않는다.
- **기존 기록:** D-004의 x축 지정, D-006의 고정 레인 등은 과거 제안으로 보존하며 사용자 승인 전 후보로만 읽는다. D-007은 기존 사용자 전달 피드백이며 이번에 교수자 원문을 확인한 것은 아니다.
- **결정 전 기록:** 사용자 자신의 태스크·대안·관찰·근거·판단·재검토 조건. 공란은 에이전트가 채우지 않는다.
- **연결:** [DESIGN_TUTOR.md](../research/DESIGN_TUTOR.md), [REVIEW.md](REVIEW.md).

## D-010 · 조사 후 실행 기반과 모듈 경계

- **상태:** implemented foundation / 2026-11-13 사용자 요청 범위의 기술적 작업. 시각화 인코딩 승인과 별개.
- **방법:** Design Study·Nested Model을 참고하는 계층별 검증 + 작은 증분 구현. 구체 적용은 프로젝트 계획이며 문헌의 보편적 정답이 아님.
- **구조:** 단일 npm 앱 안에 app/domain/data/state/vis/features를 분리. 오프라인 처리와 공개 export를 웹 소스 밖에 둠.
- **대안:** Atlas와 동일한 다언어 monorepo / 기능 경계 없는 단일 화면 구현. 현재는 독립 배포 패키지·대규모 계산 요구가 확인되지 않아 모듈 단위로 시작.
- **기술:** 기존 제안의 React + TypeScript + Vite, D3 설치 기반. **후속 D-011에 따라 React는 임시 scaffold이며 최종 선택 미정.** 법률 enum·차트·색·축·레이아웃은 확정하지 않음.
- **근거:** [개발 방법론](../development/DEVELOPMENT_METHOD.md), [고정 commit의 Atlas 구조 조사](../research/ENGINEERING_REFERENCE.md).
- **검증과 한계:** [FOUNDATION_STATUS.md](FOUNDATION_STATUS.md). 실제 시각화·실데이터·원격 CI·배포의 완료를 뜻하지 않음.

## D-011 · UI 런타임 선택 재검토

- **상태:** open / 2026-11-13 사용자 지적에 따라 D-003의 React 선택을 재개방.
- **확인 사실:** 과제는 React를 요구하지 않음. D3의 vanilla HTML 사용 가능. React·UI 위젯 라이브러리·TS·Wasm·GPU는 서로 다른 계층.
- **교정:** 정적 배포·상태 동기화·타입만으로 React 필요성을 입증한 이전 설명을 철회. 메모리와 지연의 우열은 동일 기능 실측 전 미확인.
- **후보:** Vanilla JS/TS+D3, React+D3, Vue+D3, Svelte+D3. WebGPU/Rust/Wasm 도입은 별도 미결정.
- **현 코드:** 임시 React 진입 보존; 기능·의존성 전환 없음. 기존 타입/상태/렌더러 분리로 교체 경계를 유지.
- **근거:** [공식 자료와 주장 교정](../research/FRAMEWORK_RUNTIME_REVIEW.md).
- **사용자 기록란:** 필요한 상태/상호작용 ___ / 비교 범위 ___ / 관측 ___ / 선택 ___ / 재검토 조건 ___
- **판정 게이트:** 같은 데이터·D3 출력·접근성·근거 의미에서 비교; 크기·지연·메모리·복잡도·정확성을 구분. 측정 전 추천 결론을 대신 채우지 않음.
