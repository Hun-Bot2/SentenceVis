## 데이터 계약에서 해결해야 할 사항

다음은 **구현 전 질문**이다. 이번 문서 작업에서 스키마를 확정하거나 실제 레코드를 변환하지 않았다.

1. **Judgment와 Sentence grain:** DATA의 트리/속성 표는 피고인 아래 Judgment가 있는 것처럼 보인다. 하나의 문서가 여러 피고인 선고를 포함할 때 문서 ID와 피고인별 선고 키의 관계를 명시해야 한다. 같은 문서 중복 집계 여부도 검토 대상이다.
2. **관계가 아직 독립 계약으로 기술되지 않음:** `ReasoningRelation`은 트리에 있지만 아래 JSON 요약에는 독립 relation ID·source/target·relation type·근거 배열이 없다. V2 간선과 V3 역선택을 어떤 실제 ID로 재현할지 미정이다.
3. **검토와 수용의 차이:** `reviewed`는 검토 작업을 했다는 뜻인지 정확함을 수용했다는 뜻인지 불명확하다. `rejected` 관계를 어디에 보관할지도 미정이다. 대시보드에서 검토 완료 수를 정답 수로 집계하지 않도록 판정 코드북이 필요하다.
4. **출처 차원의 혼합:** 현재 `explicit_text / llm_extracted / contextual`은 텍스트의 명시성, 생산 방법, 해석 수준을 한 enum에 섞을 수 있다. LLM이 원문 명시 관계를 정확히 추출한 경우를 현재 계약으로 어떻게 표현할지 점검한다. 이를 고치는 구체 스키마는 아직 승인되지 않았다.
5. **원문 위치와 비식별화:** offset의 기준 텍스트·Unicode 단위·끝 위치 포함 여부가 미정이다. 비식별화 전후 문자열이 바뀌면 offset·해시·인용이 동일 문서 버전을 가리키는지 확인해야 한다. 브라우저로 `original_text`를 그대로 내보내지 않는다.
6. **상태값의 불일치:** `unverified`, `unreviewed`, `reviewed`, 링크의 `verified`가 문서별로 다르게 쓰인다. 사용자 표기와 내부 enum 간 매핑·전이·검토 기준을 구현 전에 명시할 필요가 있다.
7. **집행유예의 결측과 형 종류:** `null`, 미확인, 해당 없음의 구별 및 기간 환산 불가 형의 처리 기준이 필요하다. 서로 비교 가능한 값이 확인된 행만 수치 차이 계산의 대상이 된다. 법률적 분류 기준은 판결문/전문 검토 전 확정하지 않는다.

## 주장과 평가의 보충 과제

- **연구 공백:** 기존 연구와 다르다는 제목 수준의 설명은 신규성 증명이 아니다. R9–R12의 사용자·분석 단위·태스크·근거 연결·평가·한계를 같은 항목으로 읽고, 미확인 칸은 비워 둔다.
- **태스크 용어:** `Locate`, `Compare`, `Trace/Verify`의 프로젝트 사용과 R2의 실제 분류 체계를 구별한다. 검색 대상/위치를 사전에 아는지에 따라 실제 검색 행동을 다시 기록한다.
- **비교의 정보 동등성:** TASK의 B는 문서, S는 문서+추출 경로를 제공한다. 추출된 판단 정보가 S에만 있으면 표현 효과와 정보 추가 효과가 섞일 수 있다. 평가하려는 주장에 맞춰 동일 구조화 정보 제공 여부를 검토하고 차이를 공개한다. 조건을 이번에 확정하지 않았다.
- **설계 가설 수치:** ‘채널 2–3개’, ‘5초’, ‘20–30사건’은 내부 제안이며 보편적 문헌 법칙이나 충분한 표본 보장이 아니다.
- **기말과 학회:** TASK는 학회 확장 계획이다. 해당 계획의 전부를 수업 필수 사항으로 해석하지 않는다. 이번 작업은 사람 대상 연구를 시작하지 않았다.
- **법적 주장:** 적용 조문/범행시점/판결시점 관계와 특정 사례의 이유는 이번에 검증하지 않았다. 출처 링크가 있다고 사건별 법적 결론이 확인되는 것은 아니다.

## 검증 및 AI 출처

문서만 변경했다. 앱 코드·의존성·테스트 명령이 없어 앱 빌드/동작/성능은 검증하지 않았다. Markdown 상대 링크와 코드펜스의 정합성 및 whitespace를 점검한다. 외부 링크는 실제 열람 성공 범위만 참고자료집에 기록하며 전체 기존 링크의 영구 가용성을 보장하지 않는다.

**AI 공개:** Codex가 문서 검토·공개 자료 조사·문서 수정·계산 연습 초안을 작성했다. 사용자 결정·정독·실제 데이터 검증·실험 결과는 대행하거나 생성하지 않았다. 사용자 판단 전이며 인용을 최종 보고서에 옮길 때 해당 본문을 직접 대조해야 한다.

**문서 검사 결과:** Markdown 17개 파일의 로컬 링크 49개(파일 대상)와 코드펜스 정합성 통과. README의 기존 줄끝 공백을 정리한 후 `git diff --check` 통과. 새 문서의 줄끝 공백도 별도 검사했다. 앵커와 외부 URL 전체의 자동 검증은 수행하지 않았다.
