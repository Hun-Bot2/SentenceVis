# 데이터 우선순위와 Claude 세션 대조 (2026-11-16)

## 범위와 확인 수준

사용자가 붙여준 Claude 세션 요약을 로컬 코드·인코딩 워크시트·D-013/D-014·카탈로그와 대조했다. Claude 세션 원본 전체를 별도로 열람한 것은 아니다. 수치와 법률 해석에 대한 사람 검증은 이번 작업에서 수행하지 않았다.

## 작업 우선순위

`data/priority/최우선`, `보통`, `보충`은 원본에 대한 상대 심볼릭 링크다. 원본 경로·바이트·source ID를 유지한다. `scripts/catalog/prioritize.py`로 재생성하며 파일별 사유는 비공개 `data/priority/manifest.json`에 남긴다. 파일명과 기존 조사에 의존한 분류이지 모든 문서의 내용 검토 결과는 아니다.

| 우선순위 | 대상 | 다음 정리 작업 |
|---|---|---|
| 최우선 | AI-Hub 12·115 (2개 폴더) | 통합 판결의 심급·동일 피고인·주문·이유 경로 검증. 115 원문 표시 제한 유지 |
| 보통 | 019·114·법률 지식베이스·양형기준 의결·개정형법 (5개 항목) | 원문 보완 가능성, 조문 판본, PDF 쪽 locator 확인. PDF 열로 방향 추정 금지 |
| 보충 | 통계·뉴스·논문·회의자료·혼합 ZIP 등 (23개 항목) | 각 자료의 출처·기간·단위·내용을 추가 검토. 뉴스는 D-013에 따라 최종 UI 제외 |

raw/private/processed/interim/originals/catalog는 처리 단계 저장소이므로 이동하거나 통째로 우선순위에 배정하지 않았다. 새 LLM 학습 데이터는 아직 확보·내용 검토하지 않아 분류 대상에 없다. 수집할 경우 전문·원문 ID·심급 연결 보완 여부부터 확인한다.

## 실제로 발견한 설명과 구현의 차이

`sentencing_factors.py`는 설명과 달리 `감경`, `정상을 참작`, `죄질이 나쁘다`, `엄히`도 방향 단서로 사용했다. 사용자 기준에 맞게 `유리한 정상`과 `불리한 정상`만 남겼고 PDF의 최근접 열 제목 투표 코드를 제거했다. 두 방향이 같은 문장에 함께 있으면 `unstated`로 남긴다. 문장 내 표제가 특정 요소에 실제로 적용되는지는 여전히 사람 검증이 필요하다.

실행 `run-20261116q`의 요소 결과를 재생성했다. 467문서 중 170문서·518단서는 유지됐고 방향 후보는 유리 55·불리 2·미기재 461로 변경됐다(기존 76·21·421은 폐기된 규칙의 결과). PDF 쪽은 요소 등장 위치이며 판결에 대한 적용·감경·가중의 증거가 아니다. 사람 검증 건수나 정확도를 의미하지 않는다.

## 남은 게이트

- 고정 표본에서 요소·부정문·문장 내 방향 적용 범위를 사람이 확인해야 한다.
- 조문 연결 72%와 미연결 사유는 기존 세션의 자동 결과다. 이번 작업에서 조문 전수 재검증하지 않았다.
