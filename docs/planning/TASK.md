## 0. 무엇을 추가로 증명할 것인가

SentenScope의 학회 논문은 **시각화 시스템 + 검증된 법률 데이터 + 사용자 행동의 증거**를 하나의 주장으로 연결해야 한다. 구현 자체가 아니라, 사용자가 *항소인의 주장과 법원 직권판단을 혼동하지 않으면서 관련 원문을 찾는 능력*이 연구의 중심이다.

| 주장 후보 | 필요한 증거 | 결과가 부정적이어도 가능한 해석 |
|---|---|---|
| C1. 경로형 인코딩이 판단 종류의 구별을 돕는다 | 같은 데이터에서 조건별 `origin`·`disposition`·`ex officio` 정답률, 오류 유형 | 특정 법률 용어 또는 기호가 오히려 혼란을 유발 |
| C2. 연결된 V2↔V3가 원문 검증을 돕는다 | 양쪽 판결에서 정확한 근거 위치 찾기, 명시/추출 구별, 수행 시간 | 단순 문서 검색이 일부 과제에서는 더 빠를 수 있음 |
| C3. 세 뷰 연결이 형량 변화에서 판단 근거로 이동하는 흐름을 지원한다 | T1→T2→T3 완료, 실제 탐색 경로, 질적 피드백 | V1은 유용하지만 V2의 과도한 채널이 효과를 제한할 수 있음 |

**별도로 주장하지 않을 것:** 시스템이 감형의 법적 인과 효과를 추정한다는 주장, 법원이 공정했는지 평가한다는 주장, 한국 전체 형사 판결에 대한 일반화.

**두 개의 작업 경로**

- **[COURSE] 2026-12-02 제출·12-03 발표:** 데이터 검증, 세 개의 연결된 뷰, 범례, 근거 기반 Case Study ≥3. 이 경로는 기존 `REQUIREMENTS.md`가 최우선이다.
- **[PAPER] 학회 연구:** 사전 연구윤리 검토, 도메인 조사, 비교 가능한 실험 조건, User Study, 분석 및 외부 재현 자료. 기말 이후에도 이어질 수 있다. **수업 과제에 실험을 맞추려고 윤리 절차를 생략하지 않는다.**

## 1. 연구 수행의 전제: 윤리·논문 범위부터 확정한다 [P0, 즉시]

**사람에게서 데이터를 수집하기 전에 연구 목적과 기관 절차를 확정한다.** 성균관대학교는 2026-06-11 공지에서 수업/기존 과제가 추후 연구로 확장되는 경우를 포함해 IRB 사전 심의 문제를 명시했다.[S5]

- [ ] **[P0]** 지도교수와 학회 투고 가능성, 연구 책임자·공동저자 역할, 법률 분야 자문 협력자를 논의한다. 공동저자는 실제 기여에 따라 결정한다.
- [ ] **[P0]** 성균관대학교 IRB에 인간대상연구 **심의 대상/면제 여부, 조사·녹화·화면 로그·설문·인터뷰 범위**를 공식 확인한다. 면제 여부를 연구자가 임의로 판정하지 않는다.
- [ ] **[P0]** **참가자 모집·인터뷰·파일럿·본 실험을 승인 또는 기관의 공식 판단 전에 진행하지 않는다.** 수업 동료의 편의적 피드백도 발표·논문에 데이터로 사용하려면 사전 절차에 포함한다.
- [ ] 연구설명문·동의서 초안 작성: 목적, 예상 소요, 절차, 철회권, 수집 항목, 녹화 선택 여부, 보상, 보관/파기, 문의처, 법률적 불편 가능성.
- [ ] 만 18세 이상 자발적 참여, 성적·고용·지도 관계의 압박을 피하는 모집, 법률 지식과 시각화 경험을 최소한으로 수집하는 원칙을 정한다.
- [ ] 공적 문서의 민감한 서술과 AI-Hub 원문 이용 조건을 검토한다. 판결문 속 비식별화 표식을 유지하고, 공개 데모·논문 이미지에 허용된 발췌만 사용한다.

**완료 기준:** 교수·기관과의 절차 결정 기록 + 필요한 경우 승인 문서/면제 판단 + 승인된 연구계획서가 있다. **그전에는 사람 대상 데이터 수집을 진행하지 않는다.**

## 2. 연구 포지셔닝: 기존 기술이 아닌 새로운 질문을 정의한다 [P0–P1]

**기존 법률 시각화 연구와 비교해야 기여의 범위를 지킬 수 있다.** 디자인 스터디는 도메인 문제 발굴·설계·적용·성찰의 일관된 증거를 요구한다.[S1]

- [ ] 핵심 문헌 정독: **Sedlmair et al.** 디자인 스터디 9단계; **Lam et al.** InfoVis 평가 7개 시나리오; **Munzner** Nested Model. 논문별 방법·평가 데이터·한계·적용 가능성을 1페이지 이내로 기록한다.[S1–S3]
- [ ] 법률 시각화 비교표를 확장한다: **ShowCase**, **LegalViz**, **CaseSense**, **Challenges and Opportunities for Visual Analytics in Jurisprudence**. 각 연구의 사용자·데이터 단위·핵심 인터랙션·원문 검증·평가 방법을 동일한 열로 비교한다.[S4]
- [ ] *Research Gap*을 구체화한다. 예: 사건 **결과**의 비교와 판결문 **판단 관계**의 추적은 다르며, 당사자 주장 배척과 법원 직권 파기를 구별하는 태스크가 독립적으로 평가됐는가?
- [ ] `PAPER.md`의 RQ1(Find), RQ2(Trace), RQ3(Verify)를 측정 가능한 연구 질문으로 다시 적고, 각 질문을 평가 지표 1~2개와 연결한다.
- [ ] ‘시각화 방식이 도움이 된다’는 포괄적 주장을 **대안 인터페이스 대비 구체적 장단점**으로 바꾼다. 성공 시에도 법률적 인과를 증명한 것으로 서술하지 않는다.
- [ ] IEEE VIS **Applications** 또는 **Representations & Interaction** 영역을 우선 검토하되, 최종 투고 시점의 CFP와 투고 유형(Short/Full 등)을 **다시 확인**한다. 기존 기말 과제의 5쪽 제한을 학회 제출 분량으로 오인하지 않는다.[S8]

**완료 기준:** 기존 연구 대비표 + 한 문장 연구 공백 + RQ↔태스크↔측정 매핑표 + 투고 후보 영역 검토 메모.

## 3. 도메인 이해: 가상 페르소나를 실제 사용자의 문제로 검증한다 [P1, 윤리 절차 이후]

**제안서의 페르소나는 설계 가설이다.** 비전문가가 실제로 어려워하는 지점과 전문가가 검증해야 할 법률 의미를 확인해 태스크를 다듬는다.

- [ ] **[PLAN]** 법률 분야 전문가/형사법 학습 경험자와의 반구조화 인터뷰 2~4회: `항소이유`, `판단하지 않음`, `직권판단`, `법령의 적용`, `파기`의 실제 해석과 오독 위험 확인. 인터뷰 상대의 전문 자격과 연구 협력 여부를 구별해 기록한다.
- [ ] **[PLAN]** 목표 사용자에 가까운 비법률 전공자 3~5명 대상 탐색적 관찰: 동일한 **허용된** 판결 발췌 자료에서 어떤 질문을 하고 어디에서 막히는지 기록한다.
- [ ] 관찰 결과로 T1–T3의 질문을 **사용자 언어**로 재작성하고, 가상 페르소나의 가정과 실제 발견을 별도 표시한다.
- [ ] 연구자 기대와 반대되는 관찰(원문을 안 읽음, 선 의미를 무시함, 검색어를 모름)도 원자료에 남긴다.

**완료 기준:** 참여자 특성/모집 방식 + 익명화된 인터뷰 프로토콜 + 도메인 요구 목록 + 태스크 변경 기록. `PAPER.md` 페르소나를 실사용자 자체로 혼동하지 않는다.

## 4. 실험 가능한 데이터셋: 판결 경로의 정답을 먼저 고정한다 [P1–P2]

**User Study의 정답은 LLM 추출값이 아니라 사람이 검증한 문서 근거여야 한다.** 기존 187개 사건쌍·94개 징역형 후보·43개 공동피고인 사건은 제안서의 **미검증 후보 수**로 유지한다.

- [ ] 데이터 분석 단위 확정: `case_pair`, `defendant`, `appeal_ground`, `evidence_span`의 고유 ID와 조인 규칙. 수업용 **100 items / 6 attributes** 충족 여부도 실측한다.
- [ ] 원심–항소심 사건 연결, 공동피고인 정렬, `prison_months`, 집행유예, 직권/당사자 주장, 적용 법령을 수동 검증한다. 각 경로는 원문 위치·문서 해시·검토 상태를 가진다(`VALIDATION.md` 참조).
- [ ] 법률적 **정답 주석 지침(codebook)** 작성: `origin`, `disposition`, `reasoning_change`, `source_basis`, `verification_status`, ‘정답 판단 불가능’ 기준.
- [ ] 가능하면 2명의 독립 주석자가 겹치는 사건을 판정한 뒤, 항목별 불일치·합의 규칙·일치율(적합한 지표 선택)을 기록한다. 불가능하면 단독 주석의 한계를 남긴다.
- [ ] **연습·파일럿·본 실험용 서로 다른 사건 묶음**을 확정한다. 감형, 형기 유지/집행유예 변경, 직권판단, 당사자 주장 배척 등을 포함하되 난이도와 문서 길이를 기록한다.
- [ ] 정답 검증을 완료한 후 본 실험 문항과 문서 버전을 **동결**한다. 사후에 유리한 사건만 선택하지 않는다.
- [ ] 원문 외부 공개가 허용되지 않으면 재현 패키지를 `ID·해시·비공개 생성 스크립트·인용 가능한 최소 발췌·집계 통계` 중심으로 설계한다.

**완료 기준:** `gold_cases` 목록, 주석 지침, 문항 정답과 근거 위치, 제외/보류 로그, 데이터 버전·권리 검토표. 검증이 안 된 경로는 실험에서 확정 정답으로 사용하지 않는다.

## 5. 인터페이스와 비교 기준: 무엇의 효과인지 분리한다 [P2]

**비교할 조건이 동일한 정보를 제공해야 ‘시각화’의 기여를 논할 수 있다.** 제안 기준으로 **Baseline(B)**과 **SentenScope(S)**의 2조건 비교를 우선한다.

| 조건 | 제공 정보 | 목적 |
|---|---|---|
| B — 문서 중심 기준선 | 동일 사건·피고인 식별, 양쪽 판결문 나란히 보기, 기본 검색/섹션 탐색, 동일 용어 설명 | 문서 열람만으로 문제를 해결하는 정도 파악 |
| S — SentenScope | B와 동일한 원문에 V1/V2/V3, 연결 경로, 검증 상태·범례 추가 | 경로형 인터랙션의 추가 가치 평가 |

- [ ] B와 S의 문서, 정답 정보, 법률 용어 해설, 글꼴 크기, 이용 장비를 맞춘다. B에서 중요한 정보를 의도적으로 숨겨 **허수 비교**를 만들지 않는다.
- [ ] 시각적 인코딩 사양 고정: `origin`(도형), `disposition`(직접 레이블/상태), 변경 관계(간선), 원문 출처(근거 표시), V1 형량(공통 위치). 각 채널의 의미·대안·범례를 기록한다.
- [ ] **전역 범례**가 항상 접근 가능한지, 아이콘·색·텍스처 과다로 해석 오류가 발생하지 않는지 동작 테스트한다. 채널 개수를 제한한 이유를 문헌과 태스크에 연결한다.
- [ ] 클릭/검색/범례 열기/원문 확장/원문 근거 복귀 이벤트를 **익명 세션 ID**로 로깅할 수 있도록 한다. 개별 판결 원문·검색어 전체·사용자 신원 등은 불필요하게 기록하지 않는다.
- [ ] **선택적 후속 실험**: S 내부에서 ‘전역 범례 상시 노출 vs 접힘’, ‘근거 동기화 있음 vs 없음’ 같은 ablation을 설계한다. 기초 비교 실험과 한 번에 너무 많은 조건을 섞지 않는다.

**완료 기준:** 조건별 기능 비교표, 테스트 가능한 동일한 사건 데이터, 이벤트 로그 명세, 각 인터페이스의 버전·스크린샷.

## 6. User Study 설계: 탐색적 관찰과 비교 실험을 구분한다 [P2–P3, 윤리 절차 이후]

**서로 다른 두 질문을 서로 다른 연구 방식으로 평가한다.** Lam et al.은 ‘분석·추론’, ‘사용자 수행’, ‘사용자 경험’처럼 연구 목표에 따라 평가 시나리오를 선택해야 한다고 정리했다.[S2]

### 6.1 Formative study — 사람들이 어디에서 틀리는가

- [ ] **[PLAN]** 소수의 대상 사용자(예: 3~5명)에게 S에서 T1→T2→T3을 수행하도록 하고, 화면 관찰과 반구조화 후속 질문으로 오독 지점을 수집한다.
- [ ] 법률 용어 이해, 범례 탐색, 원문 비교, 직권판단 해석의 어려움을 **문제 유형별**로 기록한다. Think-aloud 사용 여부와 실제 지시문을 명시한다.
- [ ] 인터페이스 변경 전·후를 스크린샷/결정 로그로 기록한다. Formative 참가자는 본 실험에서 제외하거나, 재참여의 학습 효과를 사전에 통제한다.

### 6.2 Summative study — 기준선보다 수행이 나아지는가

- [ ] **1차 독립변수:** 인터페이스 B vs S. 주 대상은 만 18세 이상 한국어 판결문을 읽을 수 있는 **비법률 전문가**. 법률 전문가 그룹은 추가 탐색/자문으로 분리한다.
- [ ] **[PLAN]** 동일 참가자가 두 조건을 모두 경험하는 *within-subject* 설계를 우선 검토한다. 순서는 **B→S / S→B**로 균형 배정하고, 서로 다른 난이도 유사 사건 묶음 A/B를 교차 배정한다.
- [ ] **동일 사건에 대한 정답을 먼저 학습한 뒤 다시 푸는 효과**를 피하도록 조건별 문항을 다르게 하되 난이도·형량 변화 유형·판결문 길이는 가급적 맞춘다.
- [ ] **연습 문항**과 인터페이스 튜토리얼은 두 조건에 동등하게 제공한다. 수행 중 힌트, 시간 제한, 포기 조건, 네트워크 오류 처리 규칙을 사전 정의한다.
- [ ] **참가자 규모는 고정된 학회 규칙이 아니다.** 예컨대 비교 실험 N=24~36은 초기 모집 가능성 검토용일 뿐이다. 파일럿 효과 크기/변동성과 분석 모형을 바탕으로 검정력·정밀도·실현 가능성을 검토해 최종 N을 결정한다.
- [ ] 파일럿(예: 2~4명)은 문항 난이도, 정답 판정의 모호함, 소요 시간, 로그 결함 점검용으로 실시한다. **본 실험 표본으로 무심코 합치지 않는다.**
- [ ] 실험 프로토콜·가설·1차 지표·제외 규칙·분석 계획을 데이터 수집 전에 문서로 고정한다(필요 시 비공개/익명 OSF 사전등록).[S9]

### 6.3 태스크 문항 — 기존 T1–T3을 측정 가능한 질문으로

| 과제 | 참가자에게 묻는 질문의 형태 | 채점 관측값 |
|---|---|---|
| T1 Find | “이 피고인의 1심과 항소심 징역 기간과 집행유예 변화는?” | 개월 수/상태 두 값의 정확도, 시간 |
| T2 Trace | “피고인이 주장한 쟁점은 어떻게 처리됐는가? 판결 변화에 관해 법원이 별도로 제기한 쟁점이 있는가?” | `origin`·`disposition`·직권 여부 구별, 과도한 인과 주장 여부 |
| T3 Verify | “이 관계를 뒷받침하는 1심·항소심 문장을 각각 찾아 해당 위치를 제시하라. 원문 명시인가, 추출 관계인가?” | **근거 구절/위치 정확성**, provenance 판별, 시간 |

**주의:** 참가자에게 특정 답(예: “직권 법리오해가 있다”)을 미리 알려주는 질문을 만들지 않는다. 각 문항에 `정답 없음/원문으로는 확인 불가`를 허용해 근거 없는 확신도 측정한다.

**완료 기준:** 윤리 절차 충족 + 최종 프로토콜 + 동의서/설문/문항지 + 조건 배정표 + 데이터 수집·중단·예외 처리 규칙.

## 7. 평가와 통계: 성공률뿐 아니라 오해의 형태를 분석한다 [P3–P4]

**1차 지표는 RQ와 직접 연결한다.** 만족도 설문은 보조 지표이며 원문 검증 정확도 자체를 대신하지 못한다.

- [ ] **Primary outcome** 한 가지를 사전 고정: 예를 들어 T2+T3의 **근거 일치 정답률**(판단 주체·결과 + 원문 위치를 모두 충족). 채점 단위와 부분점수·불명확 기준을 문서화한다.
- [ ] **Secondary outcomes:** T1 정답률, 과제 완료시간, 직권을 `인용`으로 잘못 분류한 비율, 추출 관계를 법원 명시로 오인한 비율, `확인 불가` 응답의 적절성.
- [ ] 사용성·부담은 필요할 때 **SUS** 또는 **NASA-TLX** 중 연구 목적에 맞는 것을 선택한다. 시각화 해독 능력의 차이가 크면 **VLAT** 또는 짧은 배경 문항의 사용 가능성도 검토한다. 설문을 전부 붙여 참가자 부담을 늘리지 않는다.[S10–S12]
- [ ] **정성 분석:** 반복 관찰된 오류를 ‘범례 미발견’, ‘기호 의미 혼동’, ‘원문 위치 실패’, ‘판단 주체 오해’, ‘추출/원문 혼동’ 같은 코드북으로 분류한다. 가능하면 독립 코딩 후 불일치 조정.
- [ ] **정량 분석:** 조건별 원점수·참가자별 짝지은 차이, 효과 크기, 불확실성 구간(예: 95% CI)을 함께 보고한다. 정확도의 종속성(반복 과제·사람·사건)을 무시하지 않도록 paired 비교/혼합효과 모형을 데이터에 맞게 선택한다.[S13]
- [ ] 제외/결측·시간 초과·로그 손상·극단값 처리 규칙을 사전 문서화하고, 주 분석과 민감도 분석을 구분한다.
- [ ] 평균만 보지 말고 참가자별·문항별 분포, 실패 사례, 기준선이 더 나았던 과제도 보고한다. 작은 표본에서 `p<0.05` 하나로 일반적 효과를 단정하지 않는다.

**완료 기준:** 익명화된 원자료 목록, 분석 코드와 재생성되는 표·그림, RQ별 결과·신뢰구간·대표 실패 사례. 결과를 얻기 전에는 `[VERIFIED]`로 표시하지 않는다.

## 8. 재현성·데이터 보호: 논문의 주장을 검토할 수 있게 남긴다 [P3–P4]

**논문과 공개 저장소를 재현 가능한 범위까지만 공유한다.** IEEE VIS Open Practices는 실험 자료·분석 코드·명세의 공유를 장려하지만, 민감하거나 라이선스에 막힌 원자료의 공개를 무조건 요구하지 않는다.[S7]

- [ ] 비공개: 원본 판결문, 법령 API 인증정보, 참여자 동의서·연락처, 연결 가능한 화면녹화, 원본 로그(`.gitignore`와 접근권한 확인).
- [ ] 공개 가능 검토 후 공유: 웹앱 코드, 데이터 변환 코드, 스키마·주석 규칙, 공개 가능한 집계/모의 자료, 실험용 문항, 분석 코드, 산출 그래프, 빌드 절차.
- [ ] 참여자 ID는 무작위 식별자로 분리하고, 연락처-연구데이터 대응표는 별도 보관한다. 보유 기간·파기 방법은 승인된 계획과 일치시킨다.
- [ ] UI 버전·commit SHA, 실험 데이터 해시, 실험 브라우저/화면 크기, 타이머·채점 방식, 실험 날짜·프로토콜 버전을 기록한다.
- [ ] AI 사용 범위(코드, 판결문 초벌 추출, 논문 수정 등)를 명확히 공개한다. 사용자 응답·비공개 판결문을 승인 없이 외부 모델에 입력하지 않는다.
- [ ] 실험 후 OSF/보충자료 공개 범위를 점검하고, 이중익명 심사를 택한다면 저장소·영상의 저자 식별 단서도 확인한다.

**완료 기준:** 공개/비공개 분리된 재현성 체크리스트 + 코드/분석 리비전 + 공유 불가 자료의 사유 명시.

## 9. 학회 논문 구성: 수업 보고서와 별도 결과물을 만든다 [P4]

**기말 제출의 5쪽 보고서는 학회 논문의 중간 산출물이다.** 연구 데이터가 추가되면 논문 구조와 강조점도 다시 조정한다.

- [ ] **Introduction:** 비전문가가 판결 결과만으로 판단 이유를 이해하기 어려운 구체적 사례 → 연구 공백 → 검증 가능한 기여 후보.
- [ ] **Related Work:** 법률 시각화, 설명 가능/근거 추적, InfoVis 인코딩·범례, 문제 주도 디자인 스터디. `RELATED_WORK.md`를 확장하되 효과를 과장하지 않는다.
- [ ] **Data & Task Abstraction:** 연결 판결의 단위와 규모, 피고인 정렬, 주석 불확실성, 실제 사용자 요구와 태스크.
- [ ] **Design & Implementation:** V1–V3, 시각적 채널/범례, 버린 대안, 연동 및 원문 근거의 기술적 구현.
- [ ] **Evaluation:** 검증된 실제 사례 3개 이상 + 탐색적 사용자 관찰 + 통제 비교 실험(진행했다면). 각각의 방법·참가자·한계 분리.
- [ ] **Discussion & Limitations:** 유효한 결과뿐 아니라 실패한 해석, 좁은 시대·죄명 범위, 법률 전문가 검증의 한계, 사람/문서 표본 편향, UI 효과와 법률 지식 효과의 분리.
- [ ] **Supplementary:** 익명화된 프로토콜, 실험 문항, 접근 가능한 코드·자료, 재현 지침, 승인/면제 기술(허용 범위), AI 사용 공개.
- [ ] 목표 학회의 **최신 CFP, 트랙, 중복투고/사전공개 정책, 분량, 제출 시점**을 제출 전에 다시 확인한다. 2027년 마감일을 현재 문서에서 추측하지 않는다.

**완료 기준:** RQ→데이터→디자인→평가→결론의 추적 가능한 논리 사슬. 설계 의도·실험 결과·연구 한계를 명확히 구분한 원고.

| 단계 | 먼저 해야 할 일 | 다음 단계 진입 조건 | 마일스톤 |
|---|---|---|---|
| **G0. 윤리·포지셔닝** | 지도교수/IRB 확인, 공백·RQ 정의 | 사람 대상 연구 착수에 필요한 공식 판단과 연구 계획 확보 | **지금** |
| **G1. 검증된 데이터** | 사건 연결·피고인 정렬·원문 정답 확정 | 재검증 가능한 사건·정답셋, 공개 허용 범위 확보 | 기말 개발과 병행 |
| **G2. 비교 가능한 UI** | B/S, 범례·시각 채널·로깅 구현 | 두 조건의 정보 동등성·기술적 안정성 확인 | 기말 이후도 가능 |
| **G3. Formative + Pilot** | 승인된 관찰, 문제 수정, 문항 점검 | 사용성 결함·문항 모호성 해결, 본 실험 계획 고정 | 윤리·시스템 준비 후 |
| **G4. 본 실험 + 분석** | 모집·교차 실험·익명화·통계 | 분석/그림/실패 사례 재현 가능 | 기말과 별도 가능 |
| **G5. 투고** | 논문·보충자료·공개 범위 점검 | 주장을 증거가 뒷받침하고 목표 CFP 충족 | 공고 확인 후 |

**정지 규칙:** IRB 상태 불명확 → 모집/측정 중단. 원문 정답 불명확 → 해당 문항 제외. 조건 간 정보 차이가 본질적으로 다름 → 효과 주장 축소. 충분한 모집 실패 → 탐색적 연구로 보고하고 통계적 일반화 포기. 학회 마감 압박 → 윤리나 검증 수준 축소하지 않음.

2. [ ] **연구 공백 표와 gold case 5건의 원문 검증 기록을 만든다.** 타당성은 검증된 판결 관계에서 시작한다.
3. [ ] **B/S 비교 실험의 T1–T3 문항 초안을 만든다.** 사람에게 실시하기 전에 법적 정답과 난이도를 점검한다.
